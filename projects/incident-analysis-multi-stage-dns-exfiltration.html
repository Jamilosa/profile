Incident Analysis - Multi-Stage DNS Exfiltration

Date: Sep 12, 2026
Tags: SOC DFIR Endpoint Security Threat Hunting Log Correlation Process Causality MITRE ATTACK SIEM DNS Wazuh Sysmon Powershell Windows

I. Executive Summary

In previous lab entries, I utilized Wazuh to aggregate network, endpoint, and application telemetry. To test these detection capabilities, I investigated a simulated, multi-stage DNS exfiltration incident on a Windows endpoint.

I correlated the events on Wazuh to track the adversary's abuse of Windows binaries. The alerts also guided me in collecting forensic evidence and breaking down the complete attack chain from the initial phishing lure to data exfiltration and persistence.

II Attack Chain Overview (MITRE ATT&CK)
Tactics Technique Implementation Summary
Initial Access Phishing (T1566) Utilized phishing campaign to lure the target into downloading and opening the Q3_Bonus_Payout.pdf.lnk
Execution PowerShell (T1059.001) Utilized PowerShell to execute the attack chain.
Stealth Double File Extension (T1036.007) Masqueraded the .lnk payload by using double file extension .pdf.lnk.
Command Obfuscation (T1027.010) Obfuscated some commands with Base64 then decoded it during execution.
File Deletion (T1070.004) Removed the main exfiltration payload after it was executed.
Discovery System Owner/User Discovery (T1033) Used whoami to identify the currently logged in user.
System Network Configuration Discovery (T1016) Used ipconfig /all to look for network configuration such as IP and MAC address.
Collection Automated Collection (T1119) Used Get-ChildItem -Recurse to get the list of .csv files on the specified folder.
Archive via Utility (T1560.001) Compressed all .csv files into a single .zip file before exfiltration.
Local Data Staging (T1074.001) Staged the archived data on the user's Temp folder.
Exfiltration Automated Exfiltration (T1020) Looped Resolve-DnsName to perform exfiltration
Data Transfer Size Limits (T1030) Set the Base64 data payload to 45-character chunks.
Exfiltration Over Alternative Protocol (T1048) Exfiltrated the data using DNS protocol by performing NULL resource record type queries
Persistence Boot or Logon Autostart Execution (T1547) Modified the registry HKCU\...\Run to run a command on user login.
III. Incident Analysis and Alert Correlation
3.1 Initial Access

The attacker used a GitHub Repository to host their malicious staging and exfiltration scripts. The attack chain started when the victim opened a disguised shortcut file (Q3_Bonus_Payout.pdf.lnk), likely delivered via phishing.

LNK Shortcut File Creation (Event ID 11)

There were two level 6 alerts pointing out that there were scripting files created on a user folder. The fact that it's in the Downloads folder and uses .pdf.lnk extension suggest that the user might have fallen victim to a phishing scheme. The image explorer.exe as well as parent folder name also suggests that the user initially downloaded and extracted a compressed archive.

The second alert shows explorer.exe appending Mark of the Web (MotW) on the file to indicate its downloaded from the internet.

data.win.system.message: "File created:

Image: C:\WINDOWS\Explorer.EXE
TargetFilename: C:\Users\jamilosa\Downloads\Q3_Bonus_Payout\Q3_Bonus_Payout.pdf.lnk
rule.description: Scripting file created under Windows Temp or User folder


data.win.system.message: "File created:

Checking the .lnk file on the endpoint revealed an Alternate Data Stream (ADS) Zone.Identifier. The ZoneId and ReferrerUrl confirmed the file was downloaded from the internet and was originally a .zip archive.

Looking at the shortcut's Target property, it contained a command to start a hidden PowerShell process that downloads and executes the next script.

3.2 Execution Chain

After the user opened Q3_Bonus_Payout.pdf.lnk, a series of PowerShell scripts executed in the background, ultimately leading to data exfiltration and persistence.

  1. Phase 1 - Staging
    • Downloads the main payload (exfil.ps1) to the disk and executes it in a new process.
    • Deletes exfil.ps1 from the disk to evade detection once execution is completed.
  2. Phase 2 - Exfiltration
    • Collects all .csv files in the specified path and compresses them into a single .zip archive.
    • Encodes the .zip archive into Base64 strings and exfiltrates the data in chunks using DNS queries.
  3. Phase 3 - Discovery & Persistence
    • Executes whoami and ipconfig /all to gather host and network information.
    • Adds a registry key (HKCU\...\Run) that triggers a hidden PowerShell task upon user login.
Phase 1 - Staging

The file that was downloaded by the .lnk shortcut, downloaded exfil.ps1 on disk, and executed it with -NoProfile -ExecutionPolicy Bypass. Empty path is expected because the parent process is running in memory using the IEX command.

To better understand the attack and identify its blast radius. I searched through archived logs for pattern that matches known fields such as Event ID, PID, and a portion of the timestamp.

Phase 3 - Discovery & Persistence

Script Block Logging captured PID 2000's execution of whoami and ipconfig /all to collect user and network information that can be used by other scripts to execute different attacks. It also modified a registry HK_Current_User\...\Run to automatically run a PowerShell task on user login. 

data.win.system.processID: 2000
data.win.system.message: "Creating Scriptblock text (1 of 1):
whoami
ipconfig /all
# Payload: Write-Host 'hello!'
$EncodedPayload = "VwByAGkAdABlAC0ASABvAHMAdAAgACcAaABlAGwAbABvACEAJwA="
$TaskCommand = "powershell.exe -WindowStyle Hidden -ExecutionPolicy Bypass -EncodedCommand $EncodedPayload"
Set-ItemProperty -Path "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" -Name "persistent_task_demo" -Value $TaskCommand -Force

ScriptBlock ID: 02fa569e-77e0-4024-8a20-7b1b01b1d2d5
Path: "

The last script added the registry key persistence_task_demo on HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run with the value of $TaskCommand in the previous alert snippet.

After the persistence was deployed. The process tree goes back to PID 16900 (stage1_exfil_ps1) and executed the remaining PowerShell script which Sysmon captured and logged File Delete Archived (Event ID 23) as it cleaned the exfil.ps1 script.

Investigation Notes

Event Viewer
I also performed investigation on the Event Viewer to look for any PowerShell Script Block events that did not match Wazuh rules. Unfortunately, Only the last 4104 (discovery and persistence) related to the attack was available because PowerShell operational logs reached its capacity limit and started to rotate the logs including other event 4104 artifacts.

This shifted the log retrieval process to the Wazuh Manager's archived logs.

IV. Findings
  • The adversary used a masqueraded .lnk shortcut file delivered likely via phishing, which initiated the attack upon user interaction.
  • The threat actor initiated the stager entirely in memory, obfuscating some payloads with Base64 encoding, and deleting staging files from the disk once they were executed.
  • Host reconnaissance and collection were highly targeted. The script specifically enumerated and compressed .csv files located within the user's ~\Documents\Data\Datasets directory, limiting the immediate blast radius to that specific dataset.
  • Data was successfully transmitted outside by chunking the compressed archive into Base64 strings and tunneling it through DNS NULL queries.
  • The attacker deployed persistence by modifying the HKCU\...\Run registry key, ensuring their payload would re-execute upon subsequent user login.

V. Lessons Learned

  • Wazuh cannot flag every malicious event, defenders must also be able to investigate events that do not generate alerts by using the context available across logs, processes, and endpoint artifacts.
  • Cyber attacks usually goes through multiple phases to avoid detections and perform advanced exploitations, these also create multiple opportunities for defenders to thwart the intrusion and prevent further compromise.
  • Attackers can use sleep to delay malware executions to prevent noticeable security alert spikes and closely tied alerts. This requires the defenders to rely on PID/PPID/GUID to map process execution chains.
  • PowerShell Script Block Logging (4104) was able to capture a Base64-encoded payload (collection and archiving) after it was decoded during execution.
